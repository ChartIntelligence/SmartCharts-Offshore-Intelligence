# CP-06 accepted Continuous Observe receipts

Isolated local integration only. No server route, interactive/frontend import, provider configuration or production deployment is added. Both `enabledLocal:true` at trusted composition and `PELORA_CP06_LOCAL=1` are required; the database write also requires an explicit transaction-local `pelora.cp06_local=on`, the named qualification database and loopback port 55432. The production Receipt Writer flag/configuration is unchanged and disabled by default.

`createAcceptedObservationReceiptWriter` accepts exactly `{jobId, capability}`. It first reads and validates the existing accepted chain with the CP-03 raw-byte, V3 evidence and binding validators. It invokes the existing historical Receipt Writer through a narrow connection adapter. The database `cp06.worker(text,uuid)` admits only the matching terminal accepted attempt/consumed claim. It never claims, renews, accepts or mutates observation state. It derives all receipt data from that accepted chain; arbitrary coordinates, request/captain/session/mission/report fields are rejected. It has no acquisition or provider port.

The database records the first receipt time using its own clock. This is evidence possession witnessed at receipt creation, not a backdated claim of historical receipt at observation acceptance. It constructs the existing receipt envelope/policy/dependency closure using exact retained capture text. Scientific capture text is never parsed and reserialized into a replacement capture. Existing historical Receipt Writer readback validates the complete exact envelope, authority digest, V3 capture reference and dependency closure. SQL performs mechanical chain checks; it does not replace scientific validators.

`cp06.envelopes` has one immutable witness per existing evidence identity, preserving the existing Receipt Writer duplicate semantics. A later accepted observation of identical evidence reuses that first witness. `cp06.links` has one immutable link per accepted logical job, including the exact CP-03 index: manifest/cell/window, accepted token, raw/evidence references, execution/binding digests, source metadata and timestamps. This separate link leaves every CP-03 record and its null receipt placeholder immutable. It distinguishes observation execution from the shared evidence witness. Receipt identity cannot change in response to caller coordinates.

Evidence-row locking serializes concurrent receipt writes. Envelope and job link commit/rollback together; duplicate requests return the existing witness. Uncertain commit acknowledgement returns unknown, and retry reads the committed chain before obtaining the same receipt. Missing/tampered linkage or failed exact readback yields `AS_OF_AUTHORITY_UNKNOWN`, never fabricated historical provenance. A receipt is not a freshness/current-intelligence claim. Absence of a receipt neither mutates nor invalidates accepted live evidence. Historical consumers must explicitly request receipt provenance and respect `receivedAt`; no reader consumer is integrated here.

The schema adds immutable `cp06.policy`, `cp06.envelopes`, `cp06.links` and two safe-path SECURITY DEFINER runtime APIs, owned by the existing nonlogin migration owner. The existing worker receives only cp06 schema USAGE and EXECUTE on `cp06.worker(text,uuid)` and `cp06.lookup(text)` in addition to its four CP-05 entry points. It receives no direct table/sequence/schema/admin privileges or ownership. PUBLIC receives no application EXECUTE. Existing owner/admin default-deny and large-object restrictions remain. `receiptPrivilegeManifest.v1.json` extends the unchanged CP-05 manifest with the three tables, three immutable triggers and two routine body hashes.

Local tests cover disabled state, receipt absence, exact linkage, shared witness/idempotence, forbidden coordinate/private inputs, unaccepted/stale attempts, explicit SQL opt-in, rollback, lost commit ACK, real process death before/after commit, tampering, direct mutation/admin denial and owner immutability. Full prior qualification and separate real restart verify exact accepted/pending/receipt records, routine definitions and grants.

Limits: the existing immutable approved-manifest authority remains trusted; schema validation cannot disprove private meaning deliberately inserted by a privileged manifest approver. Admin/migration authority remains a trust root. A receipt of identical evidence may precede a later observation job, because it proves prior possession of that exact evidence, not prior execution of that later job. No scheduling, automatic receipt retry, cleanup/retention policy, production TLS endpoint or operational rollout is qualified. No new credential, role, package, service or paid dependency is added. Ocean State, publishing and CP-07 remain unstarted.
