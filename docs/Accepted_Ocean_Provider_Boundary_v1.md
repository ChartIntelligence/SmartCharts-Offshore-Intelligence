## What availability actually means

The leaf expression is `oceanConditions != null`. The worker counts fulfilled calls
as successful, including null output whose leaf availability is false. Its aggregate
availability records that evaluation results exist. None of these checks constructs
a snapshot, scores evidence, establishes feature availability or satisfies an
Opportunity evidence gate.

Tests cover `false`, 0, a string, `true`, 1, -1, null, undefined, arrays, objects,
functions, NaN and Infinity. Every non-nullish value is available at the leaf;
null and undefined are unavailable, but invocation still fulfills. A throwing
thenable becomes a rejected worker result: `await` invokes its `then` accessor.
Nested evidence accessors are not traversed by the transparent evaluator. This is
not an accessor-safety guarantee for later consumers or JSON response serialization.

Malformed family values, null SST, nonfinite science, invented provenance, wrong
time, invalid spatial containers, inherited fields, private labels and unreviewed
snapshot objects pass through unchanged. A returned unreviewed snapshot object
therefore makes the leaf available without authenticating or constructing a snapshot.

it does not demonstrate external injection, positive eligibility, a recomputed
scientific score, negative adequacy or species equivalence. No broad species
evaluation was performed for this review.

Consumer classifications in the JSON are scoped to each consumer, not alterations
to the semantic registry:

- Provider result itself: REQUIRED_CONSUMED by the nullish availability check.
- Descendants: IGNORED by the transparent evaluator, but retained and forwarded.

- Habitat confidence, pathway, signal and observation time: OPTIONAL_CONSUMED by
  the separate opportunity interpreter.
- SST spatial samples, current structures, source/freshness, chlorophyll and quality:
  consumed by negative-adequacy assessment under its existing rules.
- Exhaustive downstream scientific/species descendants: UNKNOWN here; no claim
