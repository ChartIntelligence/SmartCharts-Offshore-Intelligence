## Demonstrated blocking requirement

Existing buildSeaSurfaceTemperaturePersistence deduplicates snapshot IDs, filters invalid/missing values, sorts represented observation times, requires at least two observations and positive elapsed observation time, and compares endpoint temperatures. Its existing confidence is min(80, 40 + sampleCount * 10). At unchanged 84 F, two observations at 00Z/08Z produce confidence 60; three at 00Z/04Z/08Z produce 70. This is feature-persistence confidence, NOT a demonstrated change in Blue Marlin final score/confidence/ranking. The existing formula is unchanged.

Three different snapshots with the SAME represented observation time have sampleCount 3 but duration zero and insufficient-history. Replacing their represented time with cycle/assessment time would manufacture elapsed observational support. Conversely, removing an intermediate valid observation changes confidence even if endpoint temperatures are identical. Therefore neither one provider frame = one assessment snapshot nor one cycle = one new observation can be imposed without an explicit governed distinction and selection policy.

Distinct assessment snapshots may be useful to preserve what each cycle evaluated, including changing evidence age and family availability. They must retain the original provider represented time/reference and must not automatically count as independent temporal observations. Accidental repetition of an exact snapshot ID is distinct from repeated assessments using unchanged source evidence. Whether three cycle records or one payload plus assessment references feeds each consumer remains unresolved. Four-hour sufficiency is NOT established.
